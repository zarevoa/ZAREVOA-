130 — FUNCIONALIDADES IMPRESCINDIBLES ZAREVOA V1

1. Objetivo

Definir las funcionalidades que deberán estar operativas para considerar que ZAREVOA V1 está en condiciones de ser probado y posteriormente presentado al público.

El objetivo no será incorporar la mayor cantidad posible de funciones, sino garantizar que el núcleo de ZAREVOA funcione correctamente de principio a fin.

2. Flujo principal obligatorio

ZAREVOA V1 deberá permitir completar este recorrido:

Inicio → creación del viaje → Travel Profile → análisis ZAREVOA → Tu ruta recomendada → aprobación o modificación → itinerario personalizado → recomendaciones.

Si este flujo no puede completarse correctamente, V1 no deberá considerarse terminada.

3. Creación de viaje

El usuario deberá poder iniciar una nueva planificación indicando la información básica necesaria, como:

- Destino o intención de viaje.
- Fechas, cuando estén definidas.
- Duración.
- Número y composición de viajeros.

La experiencia deberá ser sencilla y comprensible desde el primer momento.

4. Travel Profile

El sistema deberá recopilar las preferencias necesarias para personalizar el viaje.

Deberá incluir, según corresponda:

- Presupuesto.
- Ritmo de viaje.
- Intereses.
- Must See.
- Preferencias.
- Composición del grupo.
- Restricciones relevantes.

No se deberán solicitar datos que no tengan una función concreta dentro de la planificación.

5. ZAREVOA Engine V1

El motor deberá ser capaz de utilizar el Travel Profile y datos reales disponibles para aplicar las reglas propias de ZAREVOA.

Entre sus funciones imprescindibles estarán:

- Proponer bases adecuadas.
- Distribuir los días.
- Evitar cambios excesivos de alojamiento.
- Adaptar el viaje al ritmo seleccionado.
- Considerar tiempos de transición.
- Reducir carga en días de traslados o vuelos.
- Considerar el presupuesto.
- Ponderar intereses.
- Priorizar Must See.
- Incorporar recomendaciones For You.
- Considerar la composición del grupo sin recurrir a estereotipos.

6. Tu ruta recomendada

Antes del itinerario detallado, el usuario deberá visualizar claramente la estructura propuesta.

La pantalla deberá mostrar al menos:

- Bases o destinos principales.
- Orden de recorrido.
- Número de días.
- Información suficiente para comprender la propuesta.

El usuario deberá poder aprobarla o solicitar modificaciones.

7. Modificación sin reinicio

Una funcionalidad imprescindible será permitir cambios sin obligar al usuario a repetir todo el proceso.

Cuando sea técnicamente posible, ZAREVOA deberá recalcular únicamente las partes afectadas.

8. Generación de itinerario

Una vez aprobada la ruta, el sistema deberá crear una planificación diaria coherente.

El itinerario deberá considerar:

- Ritmo.
- Intereses.
- Distancias.
- Traslados.
- Tiempo disponible.
- Descanso.
- Presupuesto.
- Coherencia geográfica.

9. Recomendaciones contextualizadas

Las actividades y lugares no deberán aparecer como una lista genérica.

Cada recomendación deberá tener sentido dentro de:

- La ubicación.
- El día.
- El horario.
- El perfil del viajero.
- La estructura general del viaje.

10. Datos verificables

Cuando se utilicen datos objetivos variables, el sistema deberá apoyarse en fuentes fiables cuando estén disponibles.

Especial atención deberá darse a:

- Ubicaciones.
- Distancias.
- Duraciones de trayectos.
- Horarios.
- Disponibilidad.
- Precios.

La IA no deberá inventar este tipo de información presentándola como confirmada.

11. Guardado del viaje

El usuario deberá poder conservar su planificación para consultarla posteriormente.

La solución técnica podrá ser sencilla en V1, pero deberá evitar que el usuario pierda todo su trabajo al abandonar la sesión.

12. Recuperación y edición

El usuario deberá poder volver a un viaje guardado y realizar modificaciones relevantes.

El sistema deberá conservar, cuando corresponda:

- Travel Profile.
- Ruta.
- Itinerario.
- Preferencias asociadas.

13. Diseño responsive

Todas las funciones principales deberán poder utilizarse correctamente desde:

- Smartphone.
- Tablet.
- Computador.

La experiencia móvil tendrá prioridad.

14. Estados de carga

Cuando ZAREVOA esté procesando información, el usuario deberá recibir una indicación clara.

No deberá parecer que la plataforma se ha detenido mientras el Engine o servicios externos generan resultados.

15. Manejo de errores

V1 deberá gestionar errores básicos sin dejar al usuario sin explicación.

Deberán contemplarse situaciones como:

- Datos incompletos.
- Fallos de conexión.
- Servicios externos no disponibles.
- Error durante la generación.
- Información que no pueda verificarse.

Siempre que sea posible se deberá permitir reintentar sin perder el trabajo realizado.

16. Separación recomendación–monetización

Cuando existan enlaces de afiliados o reservas, el sistema deberá mantener una separación clara entre:

lo que ZAREVOA recomienda y lo que puede generar una comisión.

La utilidad para el viajero deberá ser el criterio principal.

17. Privacidad básica

Antes de recibir usuarios reales deberán estar implementados los mecanismos mínimos necesarios para:

- Informar sobre tratamiento de datos.
- Proteger información de usuario.
- Gestionar acceso a cuentas.
- Evitar exposición de credenciales.
- Aplicar las políticas legales necesarias.

18. Analítica esencial

V1 deberá permitir medir el funcionamiento del flujo principal.

Será útil registrar eventos como:

- Inicio de planificación.
- Travel Profile completado.
- Ruta generada.
- Ruta modificada.
- Itinerario generado.
- Viaje guardado.
- Interacción con recomendaciones.
- Conversión cuando exista monetización.

19. Panel administrativo mínimo

Deberá existir una forma básica de revisar el funcionamiento del sistema sin depender exclusivamente del usuario.

Podrá permitir:

- Detectar errores.
- Revisar generación de viajes.
- Identificar fallos de integraciones.
- Consultar métricas esenciales.

No será necesario construir un panel administrativo complejo para V1.

20. Criterio de aceptación

Una funcionalidad no se considerará terminada únicamente porque técnicamente responda.

Deberá comprobarse que:

1. Funciona.
2. Es comprensible.
3. Mantiene el criterio ZAREVOA.
4. No genera información engañosa.
5. Funciona correctamente en móvil.
6. Puede recuperarse de errores razonables.

21. Resultado esperado

Cuando estas funcionalidades estén integradas, ZAREVOA V1 deberá permitir que una persona pase desde una idea inicial de viaje hasta una planificación personalizada que pueda guardar, consultar y modificar.

22. Principio final

La primera versión deberá concentrar el esfuerzo en el núcleo que hace diferente a ZAREVOA.

Menos funciones, mejor conectadas y con verdadero criterio de viaje, tendrán más valor que una plataforma llena de herramientas que no comprendan realmente al viajero.
