# ZAREVOA — Checklist Maestro Antes del Lanzamiento V1

## 1. Objetivo

Este documento establece el checklist maestro que deberá completarse antes del lanzamiento público de ZAREVOA V1.

Su propósito es evitar que la plataforma sea publicada únicamente porque técnicamente funciona.

ZAREVOA deberá estar preparada desde cinco perspectivas fundamentales:

- Producto.
- Tecnología.
- Experiencia del usuario.
- Negocio.
- Seguridad y confianza.

El lanzamiento deberá realizarse cuando la experiencia completa sea suficientemente sólida para usuarios reales.

---

## 2. Regla de lanzamiento

Antes del lanzamiento deberá poder completarse correctamente el recorrido principal:

**Entrada a ZAREVOA**

↓

**Creación del Travel Profile**

↓

**Definición del viaje**

↓

**Tu ruta recomendada**

↓

**Aprobación o modificación**

↓

**Generación del itinerario**

↓

**Consulta y modificación posterior**

Si este flujo principal presenta problemas importantes, el lanzamiento deberá aplazarse hasta corregirlos.

---

# A. PRODUCTO

## 3. Propuesta de valor

- [ ] La propuesta de valor se entiende rápidamente.
- [ ] Está claro qué problema resuelve ZAREVOA.
- [ ] La plataforma no promete capacidades que todavía no posee.
- [ ] La diferencia entre ZAREVOA y un generador genérico de itinerarios es comprensible.
- [ ] El mensaje principal mantiene coherencia con la marca.

---

## 4. Travel Profile

- [ ] El usuario puede crear su Travel Profile.
- [ ] Las preguntas son comprensibles.
- [ ] El formulario no resulta innecesariamente largo.
- [ ] Se almacenan correctamente las preferencias.
- [ ] El perfil influye realmente en las recomendaciones.
- [ ] Las preferencias pueden modificarse.
- [ ] Las modificaciones se reflejan correctamente en futuros resultados.

---

## 5. Datos básicos del viaje

Comprobar que el usuario pueda definir correctamente:

- [ ] Destino.
- [ ] Fechas.
- [ ] Duración.
- [ ] Número de viajeros.
- [ ] Composición del grupo.
- [ ] Presupuesto.
- [ ] Ritmo.
- [ ] Intereses.
- [ ] Preferencias relevantes.
- [ ] Must See cuando corresponda.

---

## 6. Ritmos de viaje

Verificar los tres ritmos:

- [ ] Relajado.
- [ ] Equilibrado.
- [ ] Intenso.

Comprobar que:

- [ ] Cambiar el ritmo modifica realmente el itinerario.
- [ ] Relajado no contiene exceso de actividades.
- [ ] Equilibrado mantiene balance.
- [ ] Intenso sigue siendo realizable.
- [ ] Ningún ritmo genera jornadas absurdas.

---

## 7. Presupuesto

- [ ] Funciona el nivel Económico.
- [ ] Funciona el nivel Equilibrado.
- [ ] Funciona el nivel Confort.
- [ ] Funciona el nivel Premium.
- [ ] Puede utilizarse un presupuesto definido cuando corresponda.
- [ ] El sistema no presenta estimaciones como precios garantizados.
- [ ] La distribución del presupuesto es coherente.
- [ ] El presupuesto influye realmente en las recomendaciones.

---

# B. ZAREVOA ENGINE

## 8. Selección de bases

- [ ] La cantidad de bases es razonable para la duración.
- [ ] Se evitan cambios innecesarios de alojamiento.
- [ ] Las bases tienen sentido geográfico.
- [ ] La distribución de noches es coherente.
- [ ] No se añaden destinos únicamente para llenar días.

---

## 9. Transiciones

Comprobar que los tiempos incluyan cuando corresponda:

- [ ] Traslado al aeropuerto o terminal.
- [ ] Tiempo previo necesario.
- [ ] Viaje principal.
- [ ] Esperas razonables.
- [ ] Recogida de equipaje.
- [ ] Traslado al alojamiento.
- [ ] Check-in.
- [ ] Margen razonable.

Además:

- [ ] Los días de traslado tienen menos actividades.
- [ ] No existen actividades imposibles inmediatamente después de vuelos largos.
- [ ] El sistema diferencia tiempo de transporte y tiempo real de transición.

---

## 10. Actividades

Antes de recomendar actividades deberá comprobarse:

- [ ] Compatibilidad con intereses.
- [ ] Tiempo disponible.
- [ ] Coherencia con la ruta.
- [ ] Distancia razonable.
- [ ] Ritmo del viajero.
- [ ] Presupuesto cuando sea relevante.
- [ ] Composición del grupo cuando corresponda.

---

## 11. Must See y For You

- [ ] Must See está claramente identificado.
- [ ] For You está claramente identificado.
- [ ] For You responde al Travel Profile.
- [ ] Los lugares populares no dominan automáticamente todo el itinerario.
- [ ] Existe equilibrio entre lugares emblemáticos y personalización.

---

## 12. Composición del grupo

- [ ] La edad se utiliza como contexto y no como estereotipo.
- [ ] Las preferencias declaradas tienen prioridad.
- [ ] El sistema funciona para viajeros individuales.
- [ ] Funciona para parejas.
- [ ] Funciona para familias.
- [ ] Funciona para pequeños grupos.

---

# C. TU RUTA RECOMENDADA

## 13. Pantalla de ruta

Antes de generar el itinerario completo, comprobar que se muestre:

- [ ] Bases propuestas.
- [ ] Número de noches.
- [ ] Orden de la ruta.
- [ ] Traslados principales.
- [ ] Explicación resumida.

---

## 14. Modificación de ruta

El usuario deberá poder:

- [ ] Aprobar la ruta.
- [ ] Añadir una base cuando sea viable.
- [ ] Eliminar una base.
- [ ] Modificar noches.
- [ ] Solicitar cambios.
- [ ] Continuar sin repetir todo el formulario.

---

# D. ITINERARIO

## 15. Generación diaria

Cada día deberá mostrar de manera comprensible:

- [ ] Ubicación.
- [ ] Actividades.
- [ ] Orden lógico.
- [ ] Tiempos aproximados.
- [ ] Traslados relevantes.
- [ ] Información necesaria para comprender el día.

---

## 16. Realismo

Realizar pruebas específicas para detectar:

- [ ] Días sobrecargados.
- [ ] Distancias imposibles.
- [ ] Horarios contradictorios.
- [ ] Traslados ignorados.
- [ ] Actividades duplicadas.
- [ ] Cambios de alojamiento innecesarios.
- [ ] Presupuestos incoherentes.

---

## 17. Modificación del itinerario

Comprobar que el usuario pueda solicitar cambios como:

- [ ] Eliminar una actividad.
- [ ] Sustituir una actividad.
- [ ] Cambiar el ritmo.
- [ ] Modificar intereses.
- [ ] Cambiar presupuesto.
- [ ] Añadir o eliminar una base cuando sea viable.

El sistema deberá recalcular únicamente lo necesario cuando técnicamente sea posible.

---

# E. INTELIGENCIA ARTIFICIAL

## 18. Calidad de respuestas

- [ ] Las respuestas son coherentes.
- [ ] No existen contradicciones importantes.
- [ ] La IA respeta las reglas ZAREVOA.
- [ ] La IA utiliza correctamente el Travel Profile.
- [ ] Las explicaciones son comprensibles.
- [ ] Se evita texto innecesariamente extenso.

---

## 19. Control de información

La IA no deberá inventar como hechos:

- [ ] Precios exactos.
- [ ] Horarios actuales.
- [ ] Disponibilidad.
- [ ] Información crítica cambiante.
- [ ] Requisitos legales o migratorios sin fuentes adecuadas.

Cuando corresponda, deberán utilizarse datos actualizados provenientes de fuentes confiables.

---

# F. DATOS Y APIs

## 20. Integraciones

Para cada API activa verificar:

- [ ] Autenticación.
- [ ] Manejo de errores.
- [ ] Límites.
- [ ] Costos.
- [ ] Tiempo de respuesta.
- [ ] Datos faltantes.
- [ ] Caída temporal del proveedor.

---

## 21. Fallos externos

ZAREVOA deberá responder correctamente cuando:

- [ ] Una API no responde.
- [ ] Un proveedor devuelve error.
- [ ] No existen datos.
- [ ] Se alcanza un límite temporal.
- [ ] La IA no responde.
- [ ] Una generación falla.

El usuario deberá recibir un mensaje comprensible y nunca un error técnico incomprensible.

---

# G. EXPERIENCIA DE USUARIO

- [ ] El usuario sabe siempre dónde se encuentra.
- [ ] Los botones principales son claros.
- [ ] Volver atrás no destruye información innecesariamente.
- [ ] Las acciones importantes requieren confirmación cuando corresponde.
- [ ] No existen pantallas sin salida.

---

## 23. Móvil

- [ ] Página principal.

- [ ] Travel Profile.
- [ ] Ruta recomendada.
- [ ] Itinerario.

- [ ] Cuenta.

- [ ] Diseño.

## 50. Criterios de GO / NO-GO

### GO

ZAREVOA puede lanzarse cuando:

- El flujo principal funciona.
- Los itinerarios son suficientemente realistas.
- No existen errores críticos conocidos.
- Los datos de usuarios están protegidos.
- El sistema puede recuperarse de fallos razonables.
- La experiencia móvil es adecuada.
- Las promesas comerciales coinciden con la capacidad real del producto.

### NO-GO

El lanzamiento deberá detenerse si existe:

- Riesgo importante para datos de usuarios.
- Fallo frecuente del flujo principal.
- Itinerarios sistemáticamente imposibles.
- Problemas críticos de autenticación.
- Pagos inseguros.
- Información engañosa.
- Dependencia crítica de un servicio que no tenga manejo de fallos.

# U. PRIMEROS 30 DÍAS

## 52. Evaluación inicial

Después del primer período de uso real deberán revisarse:

- [ ] Qué porcentaje termina la planificación.
- [ ] Dónde abandonan los usuarios.
- [ ] Qué modifican.
- [ ] Qué recomendaciones aceptan.
- [ ] Qué errores se repiten.
- [ ] Cuánto cuesta cada planificación.

---

## 53. Regla final

No será necesario que ZAREVOA V1 sea perfecta.

Sí será necesario que sea:

- Útil.
- Comprensible.
- Segura.
- Realista.
- Honesta.
- Suficientemente estable.

El lanzamiento no representa el final del desarrollo.

Representa el momento en que ZAREVOA comienza a aprender de viajeros reales.

La prioridad antes y después del lanzamiento deberá mantenerse:

**crear viajes mejor pensados y convertir la tecnología en decisiones útiles para el viajero.**
