DOCUMENTO 66 — ESTRATEGIA DE ANALÍTICA, MÉTRICAS Y KPIs ZAREVOA

1. Objetivo

Definir qué deberá medir ZAREVOA desde su lanzamiento para comprender el comportamiento de los usuarios, mejorar el producto y tomar decisiones de crecimiento basadas en información real.

La analítica deberá responder principalmente:

¿Las personas encuentran ZAREVOA, entienden su propuesta, crean un viaje, obtienen valor y regresan o lo recomiendan?

2. Principio fundamental

ZAREVOA no medirá datos únicamente porque sean fáciles de obtener.

Cada métrica deberá ayudar a responder una pregunta concreta o tomar una decisión.

El principio será:

Medir → Comprender → Mejorar → Volver a medir.

3. Embudo principal

El recorrido principal del usuario podrá medirse mediante las siguientes etapas:

Visitante → Inicio de planificación → Travel Profile → Ruta recomendada → Aprobación o modificación → Itinerario → Reserva/Premium → Usuario recurrente.

Este embudo permitirá identificar dónde existen problemas o pérdidas de usuarios.

4. Adquisición

ZAREVOA deberá conocer desde dónde llegan sus usuarios.

Principales fuentes:

- búsqueda orgánica;
- acceso directo;
- redes sociales;
- publicidad;
- referencias;
- colaboraciones;
- creadores de contenido;
- enlaces compartidos;
- campañas de correo;
- otros sitios web.

No bastará con medir visitas.

Deberá analizarse qué fuentes producen usuarios que realmente planifican viajes.

5. Activación

Se considerará activación cuando un usuario alcance un punto donde comprenda realmente el valor de ZAREVOA.

Una posible definición inicial será:

Usuario que completa su Travel Profile y recibe su primera ruta recomendada.

Esta definición podrá ajustarse utilizando datos reales.

6. Métricas del Travel Profile

Se deberá medir:

- porcentaje que inicia;
- porcentaje que completa;
- tiempo de finalización;
- preguntas con mayor abandono;
- campos omitidos;
- modificaciones posteriores.

Esto permitirá simplificar el proceso sin perder información necesaria para personalizar correctamente.

7. Métricas de la ruta recomendada

La pantalla “Tu ruta recomendada” será un punto fundamental.

Se medirá:

- porcentaje que aprueba la primera propuesta;
- porcentaje que modifica;
- tipo de modificaciones;
- destinos eliminados;
- destinos añadidos;
- cambios de duración;
- cambios de ritmo;
- solicitudes de nueva propuesta.

Una tasa alta de modificaciones no necesariamente significará fracaso.

Puede indicar que el sistema está facilitando correctamente la colaboración entre usuario y plataforma.

8. Métricas del itinerario

Se analizará:

- itinerarios generados;
- itinerarios completados;
- tiempo de interacción;
- días revisados;
- actividades modificadas;
- elementos guardados;
- elementos eliminados;
- rutas compartidas;
- regreso posterior al itinerario.

El objetivo será comprender si el itinerario se convierte realmente en una herramienta útil para el viaje.

9. Retención

ZAREVOA deberá medir cuántos usuarios regresan.

Podrán analizarse ventanas como:

- 1 día;
- 7 días;
- 30 días;
- antes del viaje;
- durante el viaje;
- después del viaje.

La retención deberá interpretarse según el comportamiento natural de un producto de viajes, donde una persona puede no necesitar planificar todos los días.

10. Compartidos y recomendación

Se medirán acciones como:

- compartir ruta;
- compartir itinerario;
- invitaciones;
- enlaces enviados;
- nuevos usuarios provenientes de enlaces compartidos.

Estas métricas ayudarán a determinar si ZAREVOA posee capacidad de crecimiento orgánico.

11. Monetización

Cuando comiencen las funciones comerciales se medirán:

- clics hacia proveedores;
- reservas;
- conversiones;
- comisión promedio;
- ingreso por usuario;
- ingreso por viaje;
- usuarios Journey;
- usuarios Personal;
- tasa de conversión gratuita a premium;
- cancelaciones cuando exista información.

12. Costos

También deberán medirse los costos asociados al uso del producto.

Ejemplos:

- costo de IA por itinerario;
- costo de APIs;
- infraestructura;
- almacenamiento;
- herramientas externas;
- costo de adquisición publicitaria;
- costo de soporte.

Un aumento de usuarios no será necesariamente positivo si cada usuario genera costos superiores al valor producido.

13. Métricas de ZAREVOA Engine

El motor deberá tener métricas propias.

Entre ellas:

- tiempo de generación;
- errores;
- regeneraciones;
- modificaciones posteriores;
- aceptación de rutas;
- uso de recomendaciones;
- costo por generación;
- disponibilidad de datos externos.

Estas métricas permitirán mejorar progresivamente la calidad y eficiencia del sistema.

14. Calidad de recomendación

No toda la calidad puede medirse únicamente mediante clics.

ZAREVOA podrá incorporar mecanismos como:

“¿Esta recomendación te resulta útil?”

o evaluaciones simples después de generar una ruta.

También podrán analizarse patrones de corrección.

Si muchos usuarios eliminan sistemáticamente una determinada recomendación, deberá investigarse.

15. KPIs iniciales

Durante ZAREVOA V1 se priorizarán pocos indicadores principales:

1. Usuarios que comienzan una planificación.
2. Travel Profiles completados.
3. Rutas recomendadas generadas.
4. Porcentaje de usuarios que llegan al itinerario.
5. Usuarios que regresan.
6. Rutas o itinerarios compartidos.
7. Conversión hacia reservas o productos premium cuando estén activos.
8. Costo promedio de generación por viaje.

Estos indicadores permitirán observar el funcionamiento general sin crear un sistema excesivamente complejo.

16. Métricas de vanidad

ZAREVOA evitará tomar decisiones importantes basándose únicamente en:

- seguidores;
- impresiones;
- visualizaciones;
- visitas totales;
- “me gusta”.

Estas métricas pueden ser útiles, pero deberán relacionarse con acciones reales.

Por ejemplo:

100.000 visualizaciones + 20 planificaciones

pueden tener menos valor que:

10.000 visualizaciones + 500 planificaciones.

17. Panel de control

ZAREVOA deberá contar progresivamente con un panel interno que muestre como mínimo:

- usuarios;
- viajes iniciados;
- viajes completados;
- fuentes de adquisición;
- conversiones;
- ingresos;
- costos;
- rendimiento del Engine;
- principales destinos;
- errores.

El panel deberá permitir observar tendencias sin revisar múltiples herramientas por separado.

18. Privacidad

La analítica deberá respetar las normas aplicables de privacidad y protección de datos.

Se deberá:

- recopilar únicamente información necesaria;
- evitar exposición de datos personales;
- aplicar controles de acceso;
- establecer políticas de conservación;
- utilizar datos agregados cuando sea posible.

La medición nunca deberá justificar prácticas invasivas innecesarias.

19. Experimentación

ZAREVOA podrá realizar experimentos controlados para mejorar:

- formularios;
- textos;
- botones;
- pantallas;
- recomendaciones;
- procesos de conversión.

Cada experimento deberá definir previamente:

Hipótesis → Métrica → Resultado → Decisión.

No deberán realizarse cambios permanentes únicamente por intuición cuando exista posibilidad razonable de medirlos.

20. Revisión periódica

Las métricas deberán revisarse con una frecuencia adecuada.

Durante las primeras etapas podrán realizarse:

- revisión operativa semanal;
- análisis mensual;
- revisión estratégica trimestral.

La frecuencia podrá modificarse según el crecimiento.

21. Principio final

ZAREVOA utilizará los datos para comprender mejor a sus usuarios, no para reemplazar completamente el criterio.

Los números mostrarán qué está ocurriendo.

La investigación, los comentarios y el análisis ayudarán a comprender por qué ocurre.

La combinación será:

Datos + comportamiento + comentarios + criterio ZAREVOA.

Así, cada nueva versión deberá aprender de viajeros reales y mejorar progresivamente la experiencia de planificación.
