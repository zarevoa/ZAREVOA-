124 — PROTOCOLO DE SEGURIDAD Y ACCESO A LA DOCUMENTACIÓN

1. Objetivo

Establecer criterios básicos para proteger la documentación de ZAREVOA y controlar quién puede consultar, modificar, eliminar o compartir información del proyecto.

2. Principio general

La documentación de ZAREVOA constituye un activo del proyecto.

Su acceso deberá gestionarse de acuerdo con el nivel de responsabilidad de cada persona y evitando exposiciones innecesarias de información estratégica, técnica, comercial o relacionada con usuarios.

3. Niveles de información

La documentación podrá clasificarse, cuando sea necesario, en:

Información pública

Contenido que puede difundirse sin afectar al proyecto, como información comercial, contenidos de marketing o material publicado oficialmente.

Información interna

Documentación utilizada para desarrollar y operar ZAREVOA que no necesita estar disponible públicamente.

Información confidencial

Información estratégica, financiera, técnica, contractual, de seguridad o relacionada con datos personales que requiera mayor protección.

4. Acceso mínimo necesario

Cada colaborador, proveedor o integrante futuro del proyecto deberá disponer únicamente del nivel de acceso necesario para cumplir su función.

No será necesario entregar acceso completo al repositorio a todas las personas que participen en ZAREVOA.

5. Permisos de modificación

Los permisos para modificar documentación deberán asignarse de manera controlada.

Cuando sea posible, se diferenciarán permisos de:

- Lectura.
- Edición.
- Aprobación.
- Administración.

Los cambios relevantes deberán poder identificarse posteriormente.

6. Credenciales

Las contraseñas, claves privadas, tokens, credenciales de servicios, claves API y otros secretos tecnológicos nunca deberán almacenarse directamente dentro de documentos públicos o repositorios accesibles públicamente.

En etapas posteriores se utilizarán sistemas específicos para administrar secretos y credenciales.

7. Cuentas individuales

Cuando participen varias personas, cada una deberá utilizar su propia cuenta de acceso.

Se evitará compartir una misma contraseña entre diferentes colaboradores.

Esto permitirá identificar quién realizó cambios y revocar accesos individualmente cuando sea necesario.

8. Autenticación reforzada

Siempre que los servicios utilizados lo permitan, se recomienda activar autenticación de dos factores para las cuentas principales relacionadas con:

- Repositorios.
- Dominio.
- Hosting.
- Correo empresarial.
- Sistemas de pago.
- Bases de datos.
- Servicios tecnológicos críticos.

9. Acceso de terceros

Cuando proveedores externos necesiten acceder a documentación o sistemas de ZAREVOA, se deberá entregar únicamente el acceso indispensable y durante el tiempo necesario.

Al finalizar su participación, sus permisos deberán revisarse y, cuando corresponda, eliminarse.

10. Compartición de documentos

Antes de compartir documentación deberá verificarse:

1. Quién recibirá la información.
2. Qué información necesita realmente.
3. Si contiene datos confidenciales.
4. Si existen credenciales o información que deba ocultarse.
5. Si el medio utilizado para compartirla es adecuado.

11. Datos personales

Cuando ZAREVOA comience a recopilar información real de viajeros, los datos personales deberán mantenerse separados de la documentación general siempre que corresponda.

Su tratamiento deberá cumplir las políticas de privacidad, seguridad y normativa aplicable que se definan para la operación.

12. Revisión de accesos

Los permisos deberán revisarse periódicamente, especialmente cuando:

- Se incorpore un nuevo colaborador.
- Una persona cambie de función.
- Finalice una relación con un proveedor.
- Se detecte actividad sospechosa.
- Cambie la infraestructura tecnológica.

13. Incidentes

Ante una posible exposición, pérdida o acceso no autorizado se deberá:

1. Proteger inmediatamente las cuentas afectadas.
2. Cambiar o revocar credenciales comprometidas.
3. Revisar qué información pudo verse afectada.
4. Recuperar versiones seguras cuando sea necesario.
5. Registrar el incidente y adoptar medidas para evitar su repetición.

14. Evolución del sistema

Durante la etapa inicial de ZAREVOA, estas medidas podrán aplicarse de forma sencilla.

A medida que aumenten los usuarios, colaboradores, integraciones y datos procesados, deberá implementarse un sistema de seguridad más avanzado y formal.

15. Principio final

La seguridad documental deberá incorporarse desde el inicio sin generar complejidad innecesaria.

El objetivo será que la información correcta esté disponible para quien realmente la necesite, manteniendo protegidos los activos, decisiones y datos relevantes de ZAREVOA.
