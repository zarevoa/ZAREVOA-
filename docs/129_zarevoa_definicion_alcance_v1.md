129 — DEFINICIÓN DE ALCANCE ZAREVOA V1

1. Objetivo

Definir el alcance funcional de la primera versión pública de ZAREVOA, estableciendo qué debe estar operativo para entregar una experiencia útil, coherente y diferenciada sin intentar incorporar desde el inicio todas las posibilidades futuras del proyecto.

2. Principio de V1

ZAREVOA V1 deberá demostrar una capacidad fundamental:

comprender cómo quiere viajar una persona y transformar esa información en una ruta y un itinerario que realmente tengan sentido para ella.

La prioridad será la calidad de la planificación y no la cantidad de funciones disponibles.

3. Experiencia principal V1

El flujo central será:

Inicio → creación del viaje → Travel Profile → ZAREVOA Engine → Tu ruta recomendada → aprobación o modificación → itinerario personalizado → recomendaciones útiles.

Este flujo constituye el núcleo que deberá funcionar correctamente antes del lanzamiento.

4. Travel Profile V1

La primera versión deberá recopilar únicamente información que tenga utilidad real para la planificación.

Como mínimo podrá considerar:

- Destino o intención de viaje.
- Fechas o duración.
- Presupuesto.
- Ritmo: Relajado, Equilibrado o Intenso.
- Intereses.
- Must See.
- Composición del grupo.
- Preferencias relevantes.
- Restricciones necesarias.

Las preguntas deberán ser sencillas y evitar formularios innecesariamente largos.

5. ZAREVOA Engine V1

El motor inicial combinará:

datos reales + reglas propias ZAREVOA + IA + Travel Profile.

Deberá aplicar, como mínimo, los siguientes criterios:

- Selección razonable de bases según duración.
- Evitar exceso de cambios de alojamiento.
- Distribución coherente de días.
- Consideración del ritmo seleccionado.
- Cálculo del impacto real de traslados.
- Reducción de actividades en días de vuelos o desplazamientos importantes.
- Distribución adaptable del presupuesto.
- Ponderación de intereses.
- Diferenciación entre Must See y For You.
- Consideración de la composición y edades del grupo sin estereotipos.
- Evaluación de interés, tiempo disponible y sentido dentro de la ruta antes de recomendar una actividad.

6. Tu ruta recomendada

Antes de generar el itinerario completo, V1 deberá mostrar una propuesta clara de estructura del viaje.

El usuario podrá:

- Ver las bases recomendadas.
- Ver la cantidad de días asignados.
- Comprender la lógica general.
- Aprobar la ruta.
- Modificarla.

La modificación no deberá obligar a completar nuevamente todo el Travel Profile.

7. Itinerario personalizado

Después de aprobar la ruta, ZAREVOA generará un itinerario adaptado al viajero.

Deberá buscar equilibrio entre:

- Actividades.
- Distancias.
- Traslados.
- Descanso.
- Intereses.
- Ritmo.
- Presupuesto.
- Tiempo disponible.

La planificación deberá evitar agendas artificialmente saturadas.

8. Recomendaciones

Las recomendaciones podrán incluir, según disponibilidad de datos:

- Lugares.
- Experiencias.
- Actividades.
- Barrios o zonas.
- Gastronomía.
- Transporte.
- Alojamientos u otras opciones relevantes.

La selección deberá responder primero a la utilidad para el viajero.

9. Reservas y afiliación

V1 podrá incorporar enlaces reservables o de afiliados cuando exista una integración adecuada.

Se deberá distinguir entre:

Recomendación ZAREVOA: seleccionada porque tiene sentido para el viaje.

Opción reservable: alternativa que además permite realizar una reserva mediante un proveedor.

La comisión nunca deberá determinar por sí sola qué se recomienda.

10. Productos ZAREVOA

V1 deberá permitir presentar de manera clara los productos definidos para el proyecto, incluyendo ZAREVOA Journey y ZAREVOA Personal cuando corresponda a la estrategia de lanzamiento.

Las diferencias entre productos deberán ser comprensibles para el usuario y evitar promesas que todavía no puedan cumplirse operativamente.

11. Cuenta de usuario

La primera versión podrá incorporar una cuenta sencilla que permita:

- Guardar viajes.
- Recuperar una planificación.
- Modificar información relevante.
- Consultar itinerarios previamente creados.

La complejidad social o comunitaria no será prioritaria para V1.

12. Experiencia móvil

ZAREVOA V1 deberá diseñarse con prioridad móvil.

El producto deberá funcionar correctamente en teléfono, tablet y computador, pero el uso desde smartphone será considerado especialmente importante.

13. Datos reales

Cuando una recomendación dependa de información objetiva que pueda cambiar, ZAREVOA deberá utilizar fuentes fiables siempre que sea técnicamente posible.

Ejemplos:

- Distancias.
- Duraciones de trayectos.
- Ubicaciones.
- Información operativa de lugares.
- Disponibilidad.
- Precios cuando exista acceso fiable.

La IA no deberá presentar como hechos datos variables que no hayan sido verificados.

14. Funciones que no son imprescindibles para V1

Podrán quedar para versiones posteriores:

- Aplicaciones móviles nativas independientes.
- Comunidad social propia.
- Chat entre viajeros.
- Gamificación avanzada.
- Programa complejo de fidelización.
- Marketplace propio completo.
- Reservas directas de todos los servicios.
- Automatizaciones avanzadas.
- Funciones empresariales B2B extensas.
- Expansiones que no mejoren directamente el flujo principal.

15. Criterio para incorporar nuevas funciones

Una función nueva solo deberá añadirse a V1 si cumple al menos una de estas condiciones:

1. Es necesaria para completar el viaje.
2. Mejora significativamente la personalización.
3. Evita un problema importante para el usuario.
4. Es necesaria para operar o monetizar la primera versión.
5. Es imprescindible por seguridad, privacidad o cumplimiento.

Si no cumple estos criterios, podrá reservarse para una versión posterior.

16. Calidad antes que amplitud

Será preferible lanzar una versión con menos funciones que entregue buenas rutas y recomendaciones antes que una plataforma extensa cuya planificación resulte genérica.

El criterio ZAREVOA deberá ser perceptible desde la primera experiencia.

17. Indicador principal de éxito de V1

La pregunta fundamental será:

¿El usuario siente que esta planificación fue construida para su viaje y no simplemente generada a partir de una plantilla genérica?

La respuesta a esta pregunta deberá orientar las pruebas y mejoras de la primera versión.

18. Evolución posterior

Después del lanzamiento se utilizarán datos reales de uso, comentarios de viajeros y resultados de las pruebas para decidir qué funciones incorporar.

Las versiones posteriores podrán ampliar capacidades sin perder el núcleo de personalización.

19. Principio final

ZAREVOA V1 no necesita hacerlo todo.

Necesita hacer especialmente bien aquello que define al proyecto:

entender al viajero, construir una ruta con criterio y convertirla en un viaje personalizado, realista y útil.
